VLANs Virtuelle Netzwerke in der Veranstaltungstechnik

Strukturierte Netzwerke für komplexe Veranstaltungen (Lehrerversion)

Berufsbezogener Kontext:

Sie arbeiten als Fachkraft für Veranstaltungstechnik und sind verantwortlich für die Netzwerkinfrastruktur einer dreitägigen Hybridkonferenz mit 800 Teilnehmenden vor Ort und 1.500 Online-Teilnehmenden. Die Veranstaltung umfasst mehrere parallele Räume mit unterschiedlichen technischen Anforderungen:

  • Hauptsaal: Live-Übertragung mit 4K-Kameras, Dante-Audiosystem, DMX-Lichtsteuerung
  • Workshop-Räume: Präsentationstechnik, interaktive Displays, Videokonferenzsysteme
  • Streaming-Regie: Videomischer, Encoder, Recording-Server, Live-Streaming-Plattform
  • Publikumsnetz: WLAN-Zugang für Teilnehmende zur Event-App und zum Internet

Alle diese Systeme müssen sicher und performant über eine gemeinsame Netzwerkinfrastruktur laufen, ohne sich gegenseitig zu beeinflussen. VLANs (Virtual Local Area Networks) sind dafür die ideale Lösung.

Erwartungshorizont und Musterlösung

1. Informieren: Technische Anforderungen

Erwartete Analyse:

  • Hauptsaal:
    • 4K-Streaming: Hohe Bandbreite (25-100 Mbit/s pro Stream), niedrige Latenz
    • Dante-Audio: Sehr niedrige Latenz erforderlich (<2ms), mittlere Bandbreite, Multicast-Traffic
    • DMX-Lichtsteuerung: Niedrige Bandbreite, viele Broadcast-Pakete
  • Workshopräume: Mittlere Bandbreite, Videokonferenz benötigt QoS, isoliert von anderen Räumen
  • Streaming-Regie: Sehr hohe Bandbreite, Zugriff auf Audio/Video-Quellen erforderlich
  • Publikumsnetz: Hohe Nutzeranzahl, Internet-only, maximale Isolation aus Sicherheitsgründen
  • Management: Zugriff auf alle technischen Geräte, höchste Sicherheitsstufe

  • Native VLAN wurde nicht verwendet (Sicherheit)

VLAN99 Management - Konfiguration für Vollzugriff

🔧 Funktionsweise des Management-VLANs

Das VLAN99 (MANAGEMENT) ist als zentrales Administrationsnetzwerk konzipiert und benötigt lesenden und schreibenden Zugriff auf alle anderen VLANs. Dies wird durch folgende Konfiguration erreicht:

1. Layer-3-Switch mit Inter-VLAN-Routing

  • Der Core-Switch muss als Layer-3-Switch fungieren (Routing zwischen VLANs)
  • Jedes VLAN erhält ein Switch Virtual Interface (SVI) am Core-Switch
  • Beispiel-Konfiguration (Cisco-Syntax):
interface Vlan10 description LICHT-VLAN ip address 10.10.10.1 255.255.255.0 interface Vlan20 description AUDIO-VLAN ip address 10.10.20.1 255.255.255.0 interface Vlan30 description VIDEO-VLAN ip address 10.10.30.1 255.255.255.0 interface Vlan40 description PRODUCTION-VLAN ip address 10.10.40.1 255.255.255.0 interface Vlan50 description WORKSHOP-VLAN ip address 10.10.50.1 255.255.255.0 interface Vlan99 description MANAGEMENT-VLAN ip address 10.10.99.1 255.255.255.0 interface Vlan100 description GUEST-VLAN ip address 10.10.100.1 255.255.252.0 ! IP-Routing aktivieren ip routing

2. Access Control Lists (ACLs) für VLAN99

Um dem Management-VLAN Zugriff auf alle anderen VLANs zu gewähren, werden ACLs (Access Control Lists) konfiguriert:

! ACL für Management-VLAN: Zugriff auf ALLE VLANs erlauben ip access-list extended MGMT_TO_ALL permit ip 10.10.99.0 0.0.0.255 any ! ACL für andere VLANs: Zugriff NUR vom Management-VLAN erlauben ip access-list extended RESTRICT_TO_MGMT permit ip any 10.10.99.0 0.0.0.255 permit ip 10.10.20.0 0.0.0.255 10.10.30.0 0.0.0.255 ! Audio -> Video permit ip 10.10.30.0 0.0.0.255 10.10.20.0 0.0.0.255 ! Video -> Audio permit ip 10.10.40.0 0.0.0.255 any ! Production -> alle (außer Guest) deny ip any any ! ACLs auf VLAN-Interfaces anwenden interface Vlan10 ip access-group RESTRICT_TO_MGMT in interface Vlan20 ip access-group RESTRICT_TO_MGMT in interface Vlan99 ip access-group MGMT_TO_ALL out

3. Management-Rechner Konfiguration

Administratoren, die auf alle VLANs zugreifen müssen, werden ins Management-VLAN platziert:

  • Admin-Laptop: Anschluss an Access-Port in VLAN99
  • IP-Adresse: z.B. 10.10.99.10/24
  • Gateway: 10.10.99.1 (SVI des Core-Switches)
  • Zugriff auf andere VLANs: Funktioniert automatisch durch Routing

Beispiel: Admin-Laptop (10.10.99.10) möchte auf Dante-Mischpult (10.10.20.50) zugreifen:

  1. Laptop sendet Paket an Gateway 10.10.99.1
  2. Core-Switch routet Paket von VLAN99 nach VLAN20
  3. ACL erlaubt Traffic von Management-VLAN
  4. Paket erreicht Mischpult, Antwort erfolgt über denselben Weg

4. Sicherheitsaspekte für VLAN99

⚠️ Wichtige Sicherheitsmaßnahmen

  • Authentifizierung: Nur autorisierte Geräte im Management-VLAN (802.1X Port-Security)
  • Starke Passwörter: Switch-Management und Admin-Accounts schützen
  • Logging: Alle Zugriffe aus VLAN99 protokollieren (SYSLOG)
  • Zeitbasierte ACLs: Management-Zugriff ggf. auf Veranstaltungszeiten beschränken
  • Kein Internet: VLAN99 sollte KEINEN direkten Internetzugang haben (nur VPN falls remote)
  • Physische Sicherheit: Management-Ports an Switches mit Zugangsschutz

5. Monitoring und Troubleshooting

Das Management-VLAN ermöglicht zentrale Überwachung aller Netzwerksegmente:

  • SNMP-Monitoring: Erfassung von Switch-Status, Traffic, Fehlerraten aus allen VLANs
  • Port-Mirroring: Traffic anderer VLANs ins Management-VLAN spiegeln für Wireshark-Analyse
  • SSH-Zugriff: Fernwartung aller Switches über VLAN99
  • NTP-Server: Zeitsynchronisation für alle Netzwerkgeräte über Management-VLAN
! Port-Mirroring-Beispiel: VLAN20 (Audio) überwachen monitor session 1 source interface Vlan20 monitor session 1 destination interface GigabitEthernet0/21 ! Port 21 ist Admin-Laptop im Management-VLAN

6. Alternative: VLAN-übergreifender Switch-Management-Zugriff

Falls kein Layer-3-Switch verfügbar ist, kann VLAN99 als Native VLAN auf Trunk-Ports konfiguriert werden (nicht empfohlen aus Sicherheitsgründen) oder über einen separaten Out-of-Band Management-Port am Switch.

Netzwerk-Diagramm-Beschreibung

Erwartete Darstellung:

  • Core-Switch (Layer 3): Zentrale Routing-Instanz mit VLAN-Interfaces
  • Hauptsaal-Switch: Trunk-Verbindung zum Core, Access-Ports für Licht/Audio/Video/Production
  • Workshop-Switches (3x): Trunk zum Core, Access-Ports für VLAN 50 (Workshop)
  • Access Points: Trunk-Verbindung, VLAN 100 (Guest) für WLAN
  • Internet-Router: Nur VLAN 100 (Guest) und VLAN 99 (Management) haben Internetzugang

5. Kontrollieren: Qualitätsprüfung

Erwartete Prüfkriterien:

  • Sicherheit: Gäste-VLAN vollständig isoliert, Management-VLAN mit strengen ACLs geschützt
  • Performance: Broadcast-Trennung zwischen Licht/Audio/Video, separate VLAN-Segmente verhindern gegenseitige Störungen
  • Latenz: Dante-Audio (VLAN 20) isoliert für optimale Echtzeitperformance
  • Bandbreite: Gäste-VLAN mit größerem Subnetz (/22 statt /24) für 800 Geräte
  • Skalierbarkeit: VLAN-Schema erlaubt Erweiterung (z.B. VLAN 60 für weitere Räume)
  • Vollständigkeit: Alle Anforderungen abgedeckt (Licht, Audio, Video, Workshops, Streaming, Gäste, Management)

6. Bewerten: Reflexion

Erwartete Herausforderungen und Lösungsansätze:

  • Challenge: Dante-Audio reagiert empfindlich auf Netzwerkprobleme
    • Lösung: Dediziertes VLAN 20 nur für Dante, QoS-Priorisierung, keine anderen Dienste im Audio-VLAN
  • Challenge: 800 gleichzeitige WLAN-Nutzer können Überlast verursachen
    • Lösung: Mehrere Access Points mit Load-Balancing, Bandbreitenlimitierung pro Nutzer, separates VLAN mit Firewall-Regeln
  • Challenge: Komplexität der Inter-VLAN-Routing-Konfiguration
    • Lösung: Detaillierte ACLs dokumentieren, Layer-3-Switch mit ausreichend Performance, Testphase vor Veranstaltung
  • Challenge: Fehlersuche während der Veranstaltung bei VLAN-Problemen
    • Lösung: Management-VLAN mit Monitoring-Tools (z.B. Wireshark, SNMP), redundante Trunk-Verbindungen, Backup-Konfigurationen

Alternativen:

  • Alternative 1: Physische Trennung statt VLANs (separate Switches pro Bereich)
    • Pro: Einfachere Konfiguration, vollständige Isolation
    • Contra: Höhere Kosten, mehr Hardware, unflexibel bei Änderungen
  • Alternative 2: Weniger VLANs (z.B. Audio+Video zusammen)
    • Pro: Einfachere Verwaltung
    • Contra: Höheres Risiko von Performanceproblemen, schlechtere Fehlereingrenzung
  • Alternative 3: Cloud-basiertes Netzwerk-Management (z.B. Ubiquiti UniFi)
    • Pro: Zentrale Verwaltung, einfache Konfiguration, gute Visualisierung
    • Contra: Abhängigkeit von Internet für Management, möglicherweise weniger Kontrolle
